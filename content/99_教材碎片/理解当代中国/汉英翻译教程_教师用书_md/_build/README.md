## 源文件特征（实测，决定了处理策略）

- **原生文本型 PDF，非扫描件**：WPS 文字生成，150 页，无内嵌图片，文本层完整
  → 因此**不需要跑 OCR**，也不需要按扫描件的几何法重建阅读顺序
- **单栏排版**，页宽 595.3pt，正文左边界 `x0 ≈ 90`
- 页脚仅有页码（Calibri 9pt，`y0 ≈ 781`），**无页眉**
- 覆盖**第三单元 ~ 第十二单元，共 10 个单元**（本书不含第一、二单元的教师用书内容）

## 字体即语义标签

| 字体 / 字号 | 含义 | 输出为 |
| :--- | :--- | :--- |
| SimSun 15.9pt | 单元标题（居中，常折两行） | `# 第X单元 …` |
| SimHei 14.1pt | 节标题（教学目标 / 一~五 / 延伸阅读） | `## …` |
| SimSun 12pt | 中文正文 | 正文段落 |
| KaiTi 12pt | 楷体引文（例证原文） | `> ` 引用块 |
| TimesNewRoman 12pt | 英文正文（例证译文） | `> ` 引用块（与中文例证对照） |
| TimesNewRoman 10.4pt | **页脚注** | `**脚注：**…` |
| Calibri 9pt | 页码 | 剔除（转为 `<!-- 印刷页 N -->`） |
| Wingdings `\uf09f` | 项目符号 | `·` |

书籍结构固定为每单元 7 节：教学目标 / 一、核心概念解读 / 二、关键语句理解与翻译 /
三、重点段落分析与翻译 / 四、拓展训练 / 五、思考题 / 延伸阅读（10 × 7 = 70）。

## 关键处理点（踩过的坑）

1. **视觉行合并**：`译文` 与紧随的英文行基线相差仅 2.2pt，被 PyMuPDF 拆成两个
   `line`，按 `y0` 排序会把「译文」插进英文句中。必须先按 y 聚簇（容差 4.5pt）、
   再按 x 排序拼接，才能还原正确的行内顺序。

2. **段首缩进随段落类型变化**：普通段落是「首行 x0=114 / 续行 x0=90」，
   而 `第N句：` 段落是「首行 x0=90 / 续行 x0=138」的悬挂缩进。因此不能单靠
   「缩进变浅即断段」判断，必须结合句末标点 + 结构性种子词。

3. **`教学建议：` 类标签不能独立成段**：它需要与紧随正文同行（渲染为
   `**教学建议：**正文`），但当下一行本身是 `第N句：` 时又要断开。

4. **拉丁文句末判定**：英文段落以 `.` 结尾，若只把 `。！？` 当句末标点，
   `参考分析：` 会被粘进上一段英文里。

5. **表格续页标记**：`（续表）` / `（待续）` 是 10.4pt 行，与页脚注同字号，
   需在脚注判定前按文本模式剔除。

6. **表格内 `#`**：原书「领导核心」一行第三条译文误排为 `· # the leadership core`，
   已归一为 `· the leadership core`（全书仅 1 处）。

7. **三列表格**：p41/42/43 是「汉语 | VS | 英语」的分隔列结构（数据行中间列为空）；
   p98/99 是「源语 | 例 | 译语」的纵向合并单元格（合并格输出为空，Markdown 不支持跨行合并）。
